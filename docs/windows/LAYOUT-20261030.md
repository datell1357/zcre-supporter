## 수정

- 현황판은 폭 800 DIP 이상에서 기존 세 열 비율과 16 DIP 간격을 유지한다. 그보다 좁으면 세 영역을 24 DIP 간격의 한 열로 배치하고 외부 스크롤 하나로 끝까지 이동한다. 다시 넓혀도 같은 컨트롤을 재배치한다.
- 현황판에도 기존 다크 스크롤바 테마를 적용했다. 설정의 제목 간격은 줄바꿈 문자 대신 명시적인 여백으로 지정하고, 디버그 PasswordBox의 색·패딩·최소 높이를 주변 입력과 맞췄다.
- 계정 연결 창과 로그인 팝업은 기존 공통 창 생성 경로로 실제 작업 영역에 맞춘다. 계정 창 최소 크기도 이미 맞춰진 창 크기를 넘지 않는다.
- 테마 창 최대화 시 실제 모니터 작업 영역으로 프레임을 맞춘다. 실제 헤더 더블클릭 전후 측정에서 기존 `(-7,-7,1038,782)` 대신 `(0,0,1024,728)`을 확인했다. 작업표시줄 영역을 침범하지 않았으며 복원 크기 검사도 통과했다.

계정 데이터 형식과 생성 기능은 변경하지 않았다.

## 계정 연결과 보존

사용자가 직접 Google 로그인을 완료했다. 기존 앱 프로필과 새 로그인 프로필 모두에서 신뢰된 페이지의 공개 SDK가 제공하는 기본 계정 식별값을 사용자 지정 계정과 비교했고 일치했다. 비교 결과만 출력했으며 식별값·암호·코드·토큰은 보고서에 포함하지 않았다. 마지막 OAuth 제공자 이력까지 따로 검사한 것은 아니다.

새 로그인 프로필로 재접속해 검증된 크레딧·작업 스냅샷을 읽었고, 기존 완료 결과의 HTTPS 미디어 메타데이터도 검증했다. 금액·작업 ID·내용·미디어 URL은 생략했다. 새 생성 요청, 결제, 미디어 저장은 하지 않았다.

계정 앱 PID 37908은 정상 종료 UI를 도구로 선택할 수 없어 정확한 실행파일·프로필 확인과 설정·알림 보존 후 해당 PID만 TerminateProcess로 종료했다(종료 코드 15). 이는 정상 종료로 보고하지 않는다. 이후 보존 프로필의 계정 재접속 검사는 통과했다. 캡처 데모 PID 39212·44524는 Ctrl+Q로 정상 종료했다.

최종 검사에서 기존·신규 프로필의 preferences.json과 RecentAlerts.json은 각각의 비공개 보존본과 바이트 단위로 같았고 WebView2 프로필 디렉터리도 남아 있다. 브라우저 SDK의 정상 세션 갱신까지 바이트 불변이라고 주장하지 않는다. 계정 초기화·로그아웃·프로필 삭제는 하지 않았다.
