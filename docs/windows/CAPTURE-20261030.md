## 캡처 과정에서 확인한 수정

- 설정 창의 실제 프레임이 y=-31, 높이 788로 1024×728 작업 영역을 벗어났다. 일반 창을 대상 모니터의 작업 영역 안으로 맞추고 정상 창 테두리를 유지한다. 수정 후 실제 설정 창은 x=202, y=8, 620×712였으며 네이티브 회귀 검사가 통과했다. 실제 캡처를 위해 왼쪽 x=8로 이동한 뒤에도 작업 영역 안이었다.
- 기본 렌더링의 설정 캡처는 흰 영역이었다. 선택적 `--software-rendering` 실행 옵션을 추가해 WPF의 현재 프로세스 `RenderOptions.ProcessRenderMode = SoftwareOnly`를 적용하자 실제 설정 내용이 캡처됐다. 기본 렌더러와 Windows 설정은 바꾸지 않는다. 이 관찰만으로 GPU·DWM의 근본 원인을 단정하지 않는다.
- 앞선 동등성 검사에서 재현한 혼합 대소문자 작업 종류의 알림 필터, `audio/x-wav` 파일 확장자, 원형 메뉴의 전체 동시 실행 한도 표시도 작은 수정과 직접 회귀 검사로 반영했다.

## 검사 근거와 한계

- 코어 검사 531개 통과. 첫 호출은 저장소 인자를 누락해 fixture 경로 오류가 났으며, 절대 저장소 경로를 넘긴 최종 실행이 통과했다.

- 네이티브 원형 메뉴 검사: 6개 동작, 기존 TextBlock의 제자리 갱신, 외부 활성화 시 닫힘, 캔버스 경로 통과. 가상 합계가 `2/4 → 1/4`로 갱신됨을 확인했다. 웹 이동·생성 요청을 수행하지 않았다.
- 실제 장치 검증은 Windows 10 19044, 화면 1024×768, 작업 영역 1024×728, 배율 1이다. Windows 11 또는 복수 모니터·혼합 DPI의 실제 캡처 통과로 확대 해석하지 않는다.
