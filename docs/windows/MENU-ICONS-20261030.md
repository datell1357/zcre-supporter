# Windows 원형 메뉴 아이콘 · 2026-10-30

소스 커밋: `d6fddd4883672cac244cfec42d3b5dbc0d924ee9` (`feature/windows-port`, 로컬).

## 변경

macOS `PetQuickMenu.swift`는 SF Symbols 16포인트 아이콘과 두 줄 제목을 사용하지만 Windows `PetWindow.ShowMenu`는 제목만 표시하고 있었다. 공통 리소스 폴더에는 원형 메뉴용 이미지 파일이 없었다.

Windows에는 같은 역할을 나타내는 작은 WPF 벡터 아이콘을 추가했다. SF Symbols 파일·외부 아이콘 패키지·폰트·이미지는 다운로드하지 않았다. 기존 원형 버튼 크기와 메뉴 배치·공식 도구 경로는 유지했다. Windows에 이미 있던 캔버스 항목도 유지했다.

| 메뉴 | 항목과 아이콘 |
| --- | --- |
| 홈 · 6개 | 이미지: 사진 / 영상: 카메라 / 주짓수: 무술 동작 / 오디오: 파형 / 닫기: X / 캔버스: 아트보드와 펜 |
| 이미지 · 8개 | 이미지 생성: 사진+ / 캐릭터 시트: 인물 시트 묶음 / 부분 수정: 붓 / 배경 제거: 지우개 / 고화질 변환: 반짝임 / 크기 변환: 대각선 화살표 / 뒤로: 왼쪽 화살표 / 닫기: X |
| 영상 · 6개 | 영상 생성: 카메라+ / 고화질 변환: 반짝임 / 프레임 보간: 필름 묶음 / 영상 번역: 자막 말풍선 / 뒤로: 왼쪽 화살표 / 닫기: X |

아이콘은 고정 20×20 벡터 좌표계에 1.5 너비의 둥근 선을 사용해 16 DIP로 표시한다. 제목은 맑은 고딕 10 DIP, 줄 높이 14 DIP, 두 줄 공간 28 DIP로 배치한다. 최초 검사에서 잡힌 한국어 줄 높이 부족을 고친 값이다. 제목과 아이콘의 전체 높이는 46 DIP이며 홈 50 DIP·하위 메뉴 56 DIP 버튼 안에 배치한다.

기존 Button을 유지하고 명시적인 한국어 접근성 이름과 툴팁을 제공한다. 아이콘은 포커스·히트 테스트 대상이 아니다. 호버와 키보드 포커스에는 기존 ZCRE 연녹색 테두리와 밝아진 표면을 사용한다. 실제 스크린리더 앱의 발화 검사는 수행하지 않았다.

## 검증

- 수정 전 검사에서 `A radial action is missing its visible 16 DIP vector icon.`으로 실패해 누락을 재현했다.
- 최종 네이티브 빌드: 경고 0, 오류 0.
- 실제 WPF 홈·이미지·영상 메뉴 총 20개 버튼의 벡터 이미지, 16 DIP 크기, 아이콘·제목 분리, 버튼 영역 포함, 한국어 줄별 폭·높이, 접근성 이름·툴팁 검사가 통과했다.
- 홈 → 이미지/영상 → 뒤로 → 닫기 이동과 13개 도구의 기존 공식 경로 전달·메뉴 닫힘 검사가 통과했다. 도구 요청은 검사 안에서 받았으며 웹 페이지 열기나 실제 생성을 하지 않았다.
- 기존 요약 텍스트의 제자리 갱신, 외부 창 활성화 시 메뉴 닫힘, 애니메이션 변환 재사용 검사도 통과했다.
- 별도 레이아웃 검사에서 홈·이미지·영상 메뉴의 70/100/150% 지크 크기와 두 모서리 위치 18개 경우의 프레임 포함·분리 검사가 통과했다. 계정 창·현황판·설정 창 검사도 통과했다.

## 실제 화면과 제한

새 패키지를 실행하기 전 ZCRE 프로세스가 없음을 확인했다. 새 격리 프로필로 데모 PID 28872를 실행하고 Orca computer-use Windows provider 1.0.0으로 설정 창을 화면 왼쪽으로 이동했다. 실제 지크 몸체를 클릭해 홈 메뉴가 열리고 아이콘 6개와 제목이 보이는 것을 확인했다. 도구의 입력 결과는 `synthetic_input / unverified`였으며 성공 판단은 실제 후속 화면 변화로 했다.

투명 메뉴 창은 일반 창 목록에서 선택되지 않았다. 같은 데모의 일반 설정 창 경계 안에 보이는 실제 지크·메뉴를 창 복원 없이 촬영했다. 초기 오른쪽 영역에 기존 알림이 겹친 후보는 제외했다. 아래 원본은 개인정보가 없는 왼쪽 620×712 창 영역이다. 화면을 합성·덧칠·후처리 자르기하거나 WPF 렌더 이미지로 대체하지 않았다.
