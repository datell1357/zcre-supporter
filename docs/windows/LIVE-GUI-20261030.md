# Windows 실제 계정·결과 GUI 검증 · 2026-10-30

실기 환경은 Windows 10 IoT Enterprise LTSC build 19044, x64, 1024×768, 작업영역 1024×728, 100% DPI다. Windows 11·다중 모니터·혼합 DPI 완료 판정은 하지 않는다. 이전 전체 비교는 [전체 검증표](FULL-AUDIT-20261030.md)를 참조한다.

## 생성·과금·완료 감지

- 사용자가 승인한 짧은 알림 효과음 테스트를 **1회만** 실행했다. 웹 GUI에서는 생성 버튼을 누르지 않았다. 업로드 선택 조작이 막혀 승인된 공식 ZCRE 연결 도구로 제출했다.
- 개인 작업공간, Windows 계정 일치 검사, 최근 작업 3개 대조, GUI 잔액과 연결 도구 잔액의 일치로 같은 계정임을 확인했다. 계정 식별자와 실제 잔액은 공개 문서에서 제외했다.
- `mirelo-sfx-2.0`은 영상에 효과음을 더하는 모델이다. 직접 만든 검은 화면 입력을 사용했다. 1초 견적은 2크레딧이어서 제출하지 않았고, 1.5초 입력의 **3크레딧 견적**으로 한 번 제출했다.
- 최종 상태 `succeeded`, 과금 `settled`, 예약 3 / 차감 3 / 잔여 예약 0 / 해제 0. 작업 전후 사용 가능 잔액 차이도 3이다. 재생성·추가 유료 실행은 없었다.
- 실행 중이던 실제 계정 서포터가 해당 작업의 새 완료 항목을 `notification` 출처로 1개 기록했다. 완료 후 네이티브 현황판에서도 새 항목을 확인했다.
- 작업이 빨리 끝나 대기→실행 중 상태의 전체 GUI 전환은 관찰하지 못했다. 화면에 남은 이전 시각의 Windows 알림을 이번 작업의 새 완료 배너 증거로 사용하지 않았다.

## 실제 GUI에서 확인한 범위

| 항목 | 판정과 관찰 |
|---|---|
| 완료 항목 → 상세 현황 → 결과 창 | 실제 서포터의 최신 결과 버튼을 눌러 결과 창이 열렸다. |
| 내장 미리보기 | `미리보기 준비됨`을 확인했다. |
| 실제 재생 버튼 | 클릭 후 `재생 중` → `재생 완료`를 순서대로 확인했다. |
| 결과 저장 | **미검증.** 실제 저장 대화상자와 지정 파일명이 보였지만, 버튼 조작 후 파일이 생기지 않았다. 별도 다운로드를 이 기능 성공으로 간주하지 않는다. |
| 저장 대화상자 종료 | 설정의 `Ctrl+Q`로 앱이 정상 종료되고 소유 대화상자도 닫혔다. 강제 종료하지 않았다. |
| 설정의 `Ctrl+H` | 수정 전 창이 열리지 않는 문제를 재현했다. 수정 후 실제 계정과 격리 데모에서 상세 현황 창이 열렸다. |
| 전체 화면 캡처 | 승인된 기본 캡처 도구는 실행했으나 최종 전체 화면 파일을 저장하지 못했다. 완료로 표시하지 않는다. |
| 트레이·이미지/영상 원형 하위 메뉴의 남은 클릭 경로 | 이번 추가 실행에서 끝까지 확인하지 못했다. 기존 자동 레이아웃 검사를 실제 클릭 검증으로 대체하지 않는다. |

실제 계정의 첫 실행은 일반 렌더링, 이후 GUI 검증 실행은 `--software-rendering`을 사용했다. 후자는 도구에서 네이티브 팝업 화면을 관찰할 수 있게 했지만 제품의 기본 렌더링 설정을 바꾸지는 않았다.

저장 대화상자는 상위 결과 창의 접근성 트리에 보였지만 별도 선택 가능한 창 목록에는 없었다. 지원된 의미 기반 조작은 `coordinate input geometry is unavailable`, `element 196 is not available in cached app state for ZcreSupporter.exe`를 반환했고, 키 입력은 `window_not_focused`를 반환했다. 캡처 도구 경로에서도 `failed to activate captured window`, `window is not a usable app window`가 발생했다. 같은 오류를 무한 재시도하지 않았다.
