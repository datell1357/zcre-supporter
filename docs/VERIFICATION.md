# 검증 기록

검증일: 2026-10-25 (Asia/Seoul)

환경: Apple Silicon, macOS 27.0.1, Xcode 제공 Swift 6.4. 최소 배포 대상은 macOS 14이며, macOS 14 실기기와 Intel에서는 아직 실행하지 않았습니다.

## 0.2.6 5초 갱신·크레딧 분리·전력 최적화

- 작업 여부와 관계없이 5초 시작 간격을 목표로 조회합니다. 요청 중첩을 막고 느린 요청 완료 뒤 최소 1초 쉬며, 오류 백오프/Retry-After 동안은 더 길어집니다. 네트워크 단절/잠자기 시 진행 요청과 타이머를 취소하고 복구 후 재개합니다.
- 첫 조회의 계정/잔액 확인은 유지합니다. 이후 최근 20개 단위로 필요한 페이지만 읽고 오래된 미완료 작업은 별도 확인합니다. 작업 ID/상태를 비교하며 같은 개수의 작업 교체도 감지합니다. 60초 겹친 탐색과 첫 감시 시각 기준으로 조회 사이에 완료되거나 늦게 나타난 신규 기록을 처리합니다.
- 크레딧은 60초 주기·작업 전환 시·이후 15초 후속 확인으로 분리했습니다. 잔액 조회 실패 시 이전 계정과 같은 경우에만 마지막 잔액을 재사용하고 갱신 지연으로 표시합니다. 성공한 작업 조회와 완료 알림은 계속 처리합니다. 인증 실패·계정 변경·잘못된 작업 응답은 정상/0건으로 처리하지 않습니다. 크레딧 부족 알림도 오래된 값으로 새로 발생시키지 않습니다.
- 대기 렌더링을 12fps로 낮추고 산책/드래그/완료는 24fps를 유지합니다. 마우스 이동 이벤트로 클릭 영역을 갱신하고 실제 산책 중 20Hz, 산책 대기 중 1Hz 타이머를 사용합니다. 산책 비활성/숨김/잠자기에서는 필요 없는 타이머와 마우스 감시를 해제합니다. 이벤트 감시를 사용할 수 없으면 4Hz 위치 확인으로 대체합니다.
- Swift 54개, Node 브리지 32개가 통과했습니다. 주요 추가 검사는 같은 작업 수에서 완료/신규 작업 교체, 조회보다 늦게 노출된 완료, 오래된 미완료 작업 추적, 크레딧 갱신 실패·재시도, 계정 격리, 429 대기 시간, 크레딧 후속 정산 조회입니다. 가상 시각의 2분 동안 작업 조회 25회에 잔액 조회는 2회였으며 매번 잔액을 조회하지 않았습니다.
- 새 유료 생성·실제 완료 재생·시스템 알림 테스트를 시작하지 않았습니다. 자동 검사는 고정된 API 응답과 상태 전환으로 검증했으며 실제 공급자의 응답 지연/완료 알림 전달 전체를 보장하지 않습니다.

- arm64/x86_64 Release 빌드와 0.2.6(빌드 8) 로컬 앱·ZIP 생성, plist/개인정보 매니페스트·번들 서명 검사가 완료됐습니다. 수정 앱 재실행 후 기존 계정 연결·28 Credit·완료 기록이 유지됐고, 실제 화면에서 작업 확인은 4초 전, 크레딧 확인은 39초 전으로 분리되어 갱신되는 것을 확인했습니다. 새 유료 생성은 수행하지 않았습니다.

- 지크 클릭/간소 현황 표시와 닫기를 확인했습니다. 앱 본체의 짧은 CPU·깨우기 횟수 전후 관찰은 [0.2.6 자원 기록](RESOURCE-USAGE-0.2.6.md)에 남겼습니다. 배터리 절감률로 환산하지 않았습니다.

## 0.2.5 작업 수 일치·메뉴 모션·완료 작업 표시

- 수정 전 실제 앱의 접근성 조회에서 지크는 진행 작업 1개, 지크 카드는 이미지 0/10·영상 0/6·합산 0/16으로 표시됐습니다. 연결된 읽기 전용 기록에서 Topaz 영상 업스케일의 `submitted_provider` 상태를 확인했습니다. 숨겨진 웹 페이지의 사용량과 API 작업 목록을 서로 다른 화면에서 사용한 것이 원인입니다.
- `WorkspaceSnapshot`은 웹에서 받은 한도만 유지하고 이미지·영상·전체 진행 수를 같은 API 작업 목록에서 계산합니다. 지크 카드와 메뉴 현황을 열 때 5초 이내 최신 조회가 없으면 새로 조회하며, 진행 중 요청과 연속 클릭은 중복하지 않습니다. 평상시 15/45초 폴링 정책은 유지합니다.
- 메뉴 막대에서 토끼 몸통과 팔다리를 별도로 그리는 코드를 제거했습니다. 기존 검수된 지크 옆면 산책을 12프레임으로 줄인 22×20pt Retina 이미지를 캐시해 사용합니다. 오프라인 프레임 시트에서 밝고 어두운 배경의 실제 크기와 확대 크기를 확인했으며 몸에 추가 다리를 그리지 않습니다.
- 새 완료 말풍선은 모델·종류와 시작 시각을 두 줄로 표시하며, 알림 제목/본문에도 같은 정보를 넣습니다. 실패 알림에도 작업 정보를 넣었습니다. 작업 ID와 프롬프트는 표시하지 않습니다. 기존 저장 알림은 변경하지 않습니다.
- Swift 대상 회귀 검사 5개(오래된 웹 사용량 무시, 실제 진행 2개 집계, 완료 작업 정보, 메뉴 모션 시작/정지, 프레임 구별/고정 크기)와 Node 웹 브리지 검사 19개가 통과했습니다. 새 유료 생성, 완료 모션 테스트, 시스템 알림 테스트는 실행하지 않았습니다. 실제 작업은 수정 중 완료됐으므로 수정 후 진행→완료 전체 경로는 다음 실제 사용에서 확인해야 합니다.

- 0.2.5(빌드 7)의 arm64/x86_64 Release 컴파일, plist/개인정보 매니페스트, 번들 서명 검사가 완료됐습니다. 로컬 ad hoc 앱·ZIP을 생성했고 정식 공증은 하지 않았습니다. 재실행한 앱에서 기존 계정 연결, 28 Credit, Topaz 업스케일 완료 기록의 복원을 확인했습니다. 상세 창을 닫은 후 지크 버튼도 표시됐습니다. 진행 작업이 없는 상태이므로 수정 후 실제 진행 수 및 완료 알림 전달은 이 관찰로 검증하지 않았습니다.

## 0.2.4 서비스 상태 패널·알림 요약

- ZCRE 공식 상태 페이지와 해당 페이지의 공개 클라이언트 코드를 읽고 `GET /api/public/service-status?window=24h` 경로, 9개 모델, 상태값, 60초 갱신, 서버 시각 기준 5분 신선도 정책을 확인했습니다. 인증 없이 공개 GET의 실제 200 JSON 응답을 확인했으며 앱의 계정 쿠키·토큰과 분리했습니다.
- 상단 바 팝오버의 기본 크기를 670×560pt로 늘리고 왼쪽 340pt에 기존 계정 현황, 오른쪽에 서비스 상태를 배치했습니다. 화면 경계를 고려한 기존 크기 제한을 유지하며 두 목록은 따로 스크롤합니다.
- 서비스 상태는 현황판을 열 때 조회하고 열려 있는 동안 1분마다 갱신합니다. 닫기·잠자기 때 진행 중인 조회와 타이머를 취소합니다. 조회 실패·stale·집계 시각 차이가 5분 초과인 경우 확인 중으로 표시하고, 정상 상태도 평가된 데이터가 없으면 확인 중으로 처리합니다. HTTP Date/Age와 시스템 경과 시간으로 로컬 시계 차이의 영향을 줄입니다.
- 상단 바의 최근 알림은 최신 10개만 표시하고, 상세 현황에서는 보관된 전체 목록(현재 최대 30개)을 표시합니다. 알림 전체 보기와 상세 현황은 상세 창으로 이어집니다. 상단 바는 최근 10개만 읽음 처리하고 상세 창을 열면 전체를 읽음 처리합니다. 전체 삭제 버튼의 이름을 전체 지우기로 명확히 했습니다.
- 최종 arm64/x86_64 Release 컴파일이 완료됐고 0.2.4(빌드 6) 로컬 앱/ZIP을 생성했습니다. Info.plist·개인정보 매니페스트 문법과 번들 서명 검사가 통과했습니다. Intel 아키텍처 사용 중단 경고는 이전과 같으며 ad hoc 서명/공증 미완료 상태입니다.
- 일반 재실행 후 읽기 전용 접근성 조회에서 연결됨/90 Credit, 전체 알림, 10개를 넘는 알림 항목과 30개 보관 표시를 확인했습니다. 상단 바 화면을 선택하는 도구가 시간 초과되어 서비스 상태 패널의 실제 렌더링과 자동 갱신은 앱에서 직접 확인하지 못했습니다. 이후 앱의 읽기 전용 조회는 정상 응답했습니다.
- 모션·시스템 알림·기능 회귀 테스트는 사용자 요청에 따라 실행하지 않았습니다. 공개 API 응답과 빌드 성공을 모든 기능의 실행 검증으로 간주하지 않습니다. 변경 전 백업과 diff를 대조했으며 이전 알림 보관·설정·캐릭터 자산은 유지했습니다.

## 0.2.3 최근 기록 불러오기·로컬 저장

- 사용자 첨부 화면에는 최근 알림 제목이 있었지만 목록이 비어 있었습니다. 이전 구현은 최초 조회를 알림 감시 기준으로만 삼고, 이후 발생한 알림도 메모리에만 두어 재실행 시 사라졌습니다. 제목 표시 문제와 구분해 수정했습니다.
- 연결된 ZCRE 도구의 읽기 전용 생성 기록 조회에서 완료·실패 이력을 확인했습니다. 도구의 계정이나 인증 정보를 앱으로 복사하지 않았으며 앱은 기존 전용 WebKit 세션으로 직접 조회합니다.
- 앱의 완료·실패 작업을 최근 30개 목록에 조용히 보완합니다. 과거 기록은 읽은 상태이며 배너·소리·완료 모션을 실행하지 않습니다. 서버에서 받는 시각이 생성 시각이므로 `기존 기록 · 시작`으로 구분합니다. 새 상태 전이에 대한 기존 알림 정책은 유지합니다.
- 최근 목록·읽음 상태·지운 시점을 로컬 JSON에 저장하고 같은 계정 확인 뒤 복원합니다. 계정/작업 구분값은 SHA-256 해시를 사용하며 프롬프트·결과 URL·인증 정보는 포함하지 않습니다. 연결 해제는 파일을 삭제하고, 미리보기는 저장하지 않습니다. 지우기 이전 시작된 과거 작업은 새로고침 때 다시 가져오지 않습니다.
- arm64/x86_64 Release 빌드와 0.2.3(빌드 5) 로컬 패키징이 완료됐습니다. plist/개인정보 매니페스트 문법 및 번들 서명 검사가 통과했습니다. Intel 아키텍처 사용 중단 경고는 이전과 동일하며 정식 서명·공증 상태는 변경하지 않았습니다.
- 수정 앱을 일반 실행 후 읽기 전용 접근성 조회에서 연결됨/90 Credit, 실제 작업 완료 기록 3개, `알림 전체 보기 · 30개`, `이 Mac에 저장돼요`를 확인했습니다. 새 기록을 만들거나 완료 모션·알림 테스트 버튼을 실행하지 않았습니다. 이 관찰은 메뉴 클릭/시스템 알림 전달/재시작 복원 전체의 회귀 테스트를 뜻하지 않습니다.
- 읽기 전용 파일 확인에서 최근 30개(완료 23개/실패 7개), 중복 없는 항목, 과거 기록의 읽음 상태, 파일 0600/폴더 0700 권한을 확인했습니다. 실행 중인 프로젝트 앱은 1개이며 프로세스 상태는 S였습니다.
- 전체 diff를 수정 전 백업과 대조했습니다. 기능·회귀·UI 조작 테스트는 사용자 요청에 따라 실행하지 않았습니다.

## 0.2.2 최근 알림 화면·디버그 모션 창

- 사용자는 최근 알림의 목록뿐 아니라 제목도 보이지 않는다고 확인했습니다. 수정 전 읽기 전용 접근성 조회에서는 크레딧/동시 생성 한도를 담은 지크 간소 카드가 표시됐습니다. 이를 알림 데이터가 삭제됐다는 증거로 해석하지 않았습니다.
- 공유하던 팝오버를 메뉴 막대용/지크용으로 나눠 서로의 내용과 크기를 재사용하지 않도록 했습니다. 두 팝오버와 상세 창은 함께 뜨지 않게 닫은 뒤 전환합니다. 메뉴 막대와 상세 현황은 같은 최근 알림 컴포넌트를 사용하며 데이터가 없어도 제목과 빈 상태를 표시합니다. 저장 방식은 기존 메모리 내 최근 30개를 유지합니다.
- 설정에서 `zcrenext` 입력 시에만 현재 실행의 디버그 모드를 켭니다. 기본 상태에서는 모션 테스트 진입점을 숨기며, 디버그를 끄면 창을 숨기고 재생 중인 테스트를 종료합니다. 앱 재실행 시에는 다시 꺼집니다.
- 스크롤 없는 520×460pt 모션 창에 8방향 버튼·대기·좌우 잡힘·완료·중지를 함께 배치했습니다. 기존 2초 이동·모션 재생 코드는 유지하고, 실행 함수에서도 디버그 활성화 여부를 확인합니다. 테스트 창 닫기도 재생을 중지합니다.
- 산책 메뉴는 활성화/비활성화로 변경했고, 설정은 지크 보이기/숨기기 아래에 배치했습니다. 지크의 간소 카드 크기와 표시 정보는 유지했습니다.
- arm64/x86_64 Release 컴파일이 완료됐습니다. Intel 아키텍처 사용 중단 경고는 이전과 같습니다. 기능·회귀·UI 조작 테스트와 모션 재생은 사용자 요청에 따라 실행하지 않았습니다.

이번 변경에서는 사용자 요청에 따라 기능·회귀·UI·스모크 테스트와 동작 메뉴 재생을 실행하지 않았습니다. 아래 0.1.0의 통과 기록은 현재 변경 전체의 검증을 의미하지 않습니다.

- 상단 바 클릭/우클릭에서 지크 숨김·복원, 숨김 시 8초 배너, 읽지 않은 개수, 메모리 내 최근 30개 알림을 연결했습니다. 실제 완료/실패/크레딧 부족 전이에 기존 알림 종류 설정을 적용합니다.

- 로그인 항목 설정, 로컬 진단 JSON 내보내기, 개인정보 API 사용 사유 매니페스트, 0.2.0 버전 표시를 추가했습니다. 로그인 항목은 등록하지 않았습니다.
- Swift Release 컴파일이 완료됐습니다. Apple Silicon·Intel 공용 컴파일도 완료됐으며, 실행 파일의 두 아키텍처 모두 `LC_BUILD_VERSION minos 14.0`을 확인했습니다. Xcode 27은 빌드 중 Intel 아키텍처 사용 중단 경고를 냈으므로 Intel 실기기 실행 확인이 별도로 필요합니다.

- 빌드가 진행 중인 앱을 발견하면 교체를 중단하는 경로가 실제로 작동했습니다. 현재 프로젝트 앱을 종료한 후 패키징을 완료했습니다.
- 최종 산출물은 `dist/ZCRE Bunny.app`, `dist/ZCRE-Bunny-0.2.0-universal-local.zip`과 같은 이름의 JSON/SHA-256 파일입니다. 버전 0.2.0, 빌드 2, arm64/x86_64, `notarized: false`를 확인했습니다.

- Developer ID Application 서명 ID는 0개입니다. Apple 공증, 티켓 첨부, Gatekeeper 배포 평가 경로는 작성했으나 실행하지 않았습니다.

## 실행 문제 후속 확인 (2026-10-25)

- 일반 실행 시 프로세스가 `T` 상태로 정지되고, 직접 실행한 창도 사용자 입력을 받지 못하는 현상을 확인했습니다. 당시 LaunchServices에는 앱 등록 충돌 로그가 있었습니다. 프로세스 내부의 `isVisible` 검사만으로 실제 사용 가능 여부를 판단할 수 없었습니다.

- 11:53 재실행에서는 정상 실행 상태와 LaunchServices 등록, 전면 앱 상태를 확인했습니다. 화면 제어 도구가 실제 `ZCRE 로그인 · 계정 연결` 창과 ZCRE 웹 콘텐츠를 읽었습니다. 이후 클릭 자동 확인은 도구 시간 초과로 완료하지 못했습니다.
- 디버거 대기 표시를 관찰했으나 그것을 발생시킨 원인은 아직 확정하지 않았습니다. macOS 전역 설정은 변경하지 않았습니다. 당시 실계정 잔액과 완료 배너는 추가 확인이 필요했습니다. 후속 결과는 아래에 기록했습니다.
