# 0.2.9 지크 모션과 효과음

## 작업 자세

작업용 원본 PNG와 프레임 순서는 그대로 두고 렌더링 좌표만 좌우 반전한다. 지크가 가장 많이 걸쳐 있는 모니터의 중앙을 기준으로, 오른쪽이면 왼쪽을 보고 왼쪽이면 오른쪽을 본다. 드래그·위치 복원·크기 변경·모니터 구성 변경 직후 갱신한다. 드래그 이동 범위에는 제한을 추가하지 않는다. 상단 바 달리기 방향은 바꾸지 않는다.

## 실패 울음

- 기존 승인된 정면 지크 이미지를 기반으로 Grok 구독과 sprite-gen의 `video-set` → 프레임 추출 → `once-return` 경로를 사용했다.
- 털썩 앉아 양손으로 눈을 비비며 우는 자세, 열린 입과 들썩이는 어깨, 옆으로 튀는 파란 눈물을 확인했다. 약 5.04초·64프레임·일회 재생이며 마지막에 서 있는 자세로 돌아온다.
- `body_h=384`로 기존 모션의 기준 신장을 유지한다. 앉았을 때 몸을 키워서 채우지 않는다. 원본 영상 121프레임에서 프레임 바깥으로 잘린 피사체는 없었다. 추출 시트의 한 프레임에서는 떨어지는 눈물 끝이 자동 크롭의 아래 경계에 닿는다.
- 실제 작업이 실패로 바뀐 이벤트에서만 실행한다. 첫 연결의 과거 실패 이력이나 단순 네트워크 오류는 울음 이벤트가 아니다. 기존 실패 알림 설정을 따른다.
- 드래그가 우선하며 울음·완료 반응 동안 산책과 타자음은 멈춘다. 반응 후 남은 작업이 있으면 작업 자세로 복귀한다.
- **설정 → 디버그 모드 → 지크 모션 테스트 → 작업 실패 · 한 번 재생**에서 직접 재생할 수 있다. 이 버튼은 서버 요청·크레딧 변경·시스템 알림을 만들지 않는다.

제작 원본은 개발 작업 폴더의 `art/zic/cry-v1/`, 최종 앱 리소스는 `Sources/ZCREBunny/Resources/Zic/cry.png`와 `cry.json`, 검토 기록은 `reviews/2026-10-26-cry-motion.json`이다. 소스 전달본에는 최종 리소스와 검토 기록을 넣고 제작 영상은 제외한다.

## 타자음이 다른 소리를 방해하는 문제 대응

기존 코드는 AVAudioPlayer의 무한 반복으로 타자음을 계속 출력했다. 다른 앱을 중지하거나 독점 오디오 모드를 설정하는 코드는 발견하지 못했다. 사용자가 겪은 특정 장치에서의 출력 차단은 재현하지 못했으므로 단일 원인을 확정하지 않는다.

이번 버전은 무한 반복을 제거했다. 약 1초만 타자를 재생하고 5초 쉬며, 멈출 때 플레이어를 해제한다. CoreAudio가 다른 프로세스의 출력 또는 입력 실행을 보고하면 타자음을 시작하지 않거나 중지한다. 재생 중 확인 간격은 0.5초, 다른 소리로 쉬는 동안은 최소 2초다. 음소거·지크 숨김·잠자기·앱 종료·드래그·완료·실패로 전환하면 예약 작업도 취소한다. 효과음 스위치와 음량 설정은 유지한다.

이 확인은 [CoreAudio 오디오 실행 상태](https://developer.apple.com/documentation/coreaudio/kaudioprocesspropertyisrunningoutput)를 읽는 작업이다. 오디오 샘플·앱 이름을 읽거나 녹음하지 않고, 프로세스 목록을 저장·전송하지 않는다. 마이크/화면 녹화 권한을 요청하지 않으며 다른 앱의 재생 상태, 기기, 시스템 음량을 변경하지 않는다. 속성 조회를 지원하지 않는 구형 macOS는 장치 사용 여부를 확인해 보수적으로 타자음을 양보한다. 조회 실패도 타자음 재생 허가로 간주하지 않는다.

검증은 무음 재생 대역으로 중복 방지·유한 재생·휴지기·다른 소리 시작/종료·실패 모션·숨김/음소거·설정 저장을 확인했다. 이 Mac에서 CoreAudio 읽기 경로가 오류 없이 반환하는 것도 확인했다. 특정 Bluetooth/USB/가상 오디오 장치에서 기존 증상이 사라지는지는 실제 사용자 환경에서 추가 확인해야 한다. 실제 소리를 자동 재생해 청취하거나 다른 앱 소리를 캡처하는 검사는 하지 않았다.
