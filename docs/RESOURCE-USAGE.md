# ZCRE 서포터 0.2.4 자원 사용 관찰

측정: 2026-10-25 17:36:21–17:37:51 KST, 약 89.7초. 앱·사용자 설정은 변경하지 않았다.

## 환경과 방법

- 현재 Mac의 macOS 앱, 외부 전원 사용(AC Power). 지크 표시/산책 켬, 사용자 배율 70%.
- 앱 본체와 ZCRE 저장소 경로를 사용하는 WebKit GPU·WebContent·Networking 3개 프로세스를 포함했다. 다른 앱의 WebKit은 제외했다.
- 5초 간격으로 `proc_pid_rusage`의 누적 CPU·physical footprint를 읽었다. CPU 시간은 이 Mac의 mach timebase로 나노초로 변환하고 `ps` 누적 시간과 대조했다. CPU 100%는 한 코어에 해당한다.
- `nettop`으로 대상 프로세스의 송수신 누적 바이트를 30초 간격, 총 4회 관찰했다. 패킷 내용·인증 정보는 수집하지 않았다. 이 구간에서 트래픽이 표시된 프로세스는 ZCRE의 WebKit Networking이었다.
- 앱 시작 시 웹 리소스 로딩은 측정 구간 밖이다. 배터리 감소율·전체 GPU/WindowServer 전력·장시간 전력은 측정하지 않았다. 배터리 시간당 소모율로 환산할 근거는 없다.

시간당 트래픽은 짧은 관찰의 단순 환산이다. 초기 로딩·계정 변경·작업 수·웹 세션 갱신·메뉴 사용에 따라 달라진다. 숨김/표시 비교나 작업 생성 부하 테스트는 하지 않았다.

## 코드상 서버 요청량

- 기본 한 주기: 잔액 1회 + 작업 목록 1회. 작업 없음은 완료 후 45초 대기하므로 약 160 GET/시간, 작업 중은 15초 대기하므로 약 480 GET/시간. 실제 요청 시간만큼 빈도는 낮아지며, 페이지 추가·오래된 진행 작업 개별 조회·웹 페이지 자체 요청·로그인 갱신은 이 계산에 포함되지 않는다.
- 첫 연결은 작업 목록을 최대 20페이지(50개씩) 가져온다. 현재 UI의 최신 10개 제한은 네트워크 페이지 크기를 바꾸지 않는다.
- 서비스 상태: 메뉴가 열린 동안 모든 서비스 묶음을 60초마다 1회, 약 60 GET/시간 추가. 닫기/잠자기 때 중지한다.
- 공개 서비스 상태 응답 1회는 압축 본문 1,444 bytes, HTTP 응답 헤더 2,751 bytes, 압축 해제 본문 22,628 bytes였다. 대략 본문+응답 헤더 0.25 MB/시간이며 요청 헤더·TLS·연결 비용은 별도다. 공개 응답 크기는 시점에 따라 달라진다.
- 애니메이션은 로컬 이미지라 프레임별 서버 요청을 만들지 않는다. 앱은 유료 생성/결제 요청을 수행하지 않는다.
- 1대의 평균 조회 빈도는 낮은 편이지만 서비스의 공식 호출 한도와 서버 처리 비용을 확인한 것은 아니므로 무부하를 보장하지 않는다. 다수 사용자 배포 시 요청량은 합산된다.

## 배터리 관점의 개선 후보

- 표시 중인 지크는 약 24fps로 계속 그리며, 이동/마우스 위치 확인 타이머가 초당 20회 실행된다. 산책만 꺼도 두 갱신 경로는 유지된다.
- 지크 숨김/시스템 잠자기는 캐릭터 렌더링과 이동 타이머를 중지한다. 숨김 상태의 실제 감소량은 별도 측정하지 않았다.
- 대기 모션의 갱신 빈도 감소, 이동 중에만 고빈도 타이머 사용, 무작업 조회 간격 확대, 첫 조회 범위 축소가 후보이다. 서버가 지원하는 이벤트 알림/증분 조회와 공식 호출 정책도 배포 전 검토할 필요가 있다.
