# 결과 조회·다운로드 안정성과 진단

- 작업 감시 5초와 크레딧 60초 일정은 변경하지 않는다.
- 자동 업데이트 확인은 12시간, 수동 확인은 최소 60초 간격으로 분리한다. GitHub 403/429의 서버 대기는 양쪽 모두 지킨다. 대기 중 수동 클릭에는 다음 확인 가능 시각을 표시한다.
- 결과 조회는 네이티브 25초 제한과 Task 취소를 적용한다. 결과창 다시 확인 중에는 기존 결과를 유지한다. 로그아웃·계정 전환·웹 페이지 이동 시 이전 요청을 무효화한다.
- 다운로드는 사용자 선택 후에만 시작한다. 크기를 아는 응답에는 진행률과 받은/전체 용량, 모르는 응답에는 받은 용량을 표시한다. 취소·저장 폴더 열기를 제공한다.
- 401/403/404/410에서만 캐시를 건너뛰어 주소를 갱신하고 한 번 다시 받는다. 메타데이터의 기존 최소 간격과 서버 재시도 대기는 우회하지 않는다. 5xx·취소·로컬 저장 오류는 자동으로 반복하지 않는다.
- 전체 수신을 임시 파일에서 마친 후 목적지와 같은 볼륨의 임시 파일을 교체한다. 실패·취소 시 이전 파일을 보존한다. 저장 위치 쓰기 권한·여유 공간·네트워크 지연은 구분해 안내한다.
- 미리보기는 청크로 임시 파일에 받고 최대 12MiB·1100px 제한을 유지한다. 같은 URL의 동시 조회는 병합하고, 한 뷰의 취소가 다른 뷰의 조회를 중단하지 않는다. 계정 전환은 대기 중 이미지와 메모리 캐시를 함께 지운다.

## 진단 집계

고정된 7가지 기능(accountSnapshot, creatorMetrics, serviceStatus, updateCheck, resultLookup, resultPreview, resultDownload)에 대해 메모리에서만 요청 횟수·성공·실패·취소 수, 마지막 성공 시각·처리 시간·HTTP 상태·정형 결과 코드를 집계한다. 앱 재시작 시 초기화된다.

계정 스냅샷과 메트릭 수치는 네이티브 기능 호출 단위다. WebKit 내부의 모든 HTTP 요청 수나 압축 전송 바이트를 측정한 것으로 해석하면 안 된다. 결과 메타데이터·이미지 캐시 적중은 별도 요청으로 더하지 않는다.

URL, 인증값, 계정 ID, 프롬프트, 오류 원문을 집계 API로 전달하지 않는다. 자동 업로드·상시 로그 파일을 추가하지 않는다. 설정의 진단 내보내기를 사용자가 실행하면 기존 정보와 집계를 함께 JSON(formatVersion 2)으로 저장한다.

## 검증

외부 통신 없는 URLProtocol 대역과 가상 시계로 수동/자동 확인 분리, Retry-After, 결과 조회 시간 제한·취소·늦은 응답 무시, 캐시 우회, 진행률·청크 수신·용량/잘림 제한, 만료 주소 한 번 재시도, 저장 실패/취소 시 기존 파일 보존, 이미지 동시 조회 병합과 축소, 진단 허용 필드를 검증한다. 이 검사만으로 실계정 결과 저장 또는 GUI 종단 간 검증을 완료했다고 보지 않는다.

### 창 없는 실계정 점검

기존 앱 프로세스를 모두 종료한 후 설치된 앱의 실행 파일에 `--verify-live-account <절대 경로의 JSON 보고서>`를 전달하면 메뉴 막대·펫·로그인 창·알림을 생성하지 않고 기존 WebKit 로그인 세션으로 읽기 전용 점검을 수행한다. 5초 간격 스냅샷과 초기 정산 구간 이후 캐시 재사용, 메트릭, 서비스 상태, 업데이트 확인, 기존 완료 결과의 메타데이터·캐시·강제 갱신과 파일 저장을 검사한다. 선택한 결과가 이미지일 때 미리보기 디코딩도 검사한다. 생성·결제 요청은 없으며 다운로드는 64MiB 이내로 제한한다.

보고서에는 검사별 성공 여부와 채널 수·받은 바이트 수만 기록하고 URL·인증값·계정 ID·작업 내용은 기록하지 않는다. 선택한 결과 파일은 보고서와 같은 폴더에 `verified-result.*`로 저장되므로 공개 저장소에 올리지 않는다. 이 점검은 버튼 클릭·영상 재생·OS 알림의 화면 검증을 대체하지 않는다. 일반 실행에는 영향을 주지 않는다.
