# 앱 내 웹 기능 비과금 검증 · 2026-11-25

대상은 `/Applications/ZCRE 서포터.app`의 작업 창과 로그인된 실제 ZCRE 계정이다. 합성 이미지·짧은 영상·오디오만 새 입력에 사용했고, 기존 생성물은 미리보기와 다운로드 경로 확인에만 사용했다. 크레딧을 차감하는 생성·변환·번역·내보내기 실행은 하지 않았다. 검증 전후 표시 잔액은 같았다.

## 당시 동작하지 않았거나 완료까지 검증할 수 없었던 부분

1. **ZCUT 내보내기:** 당시 설치본에서는 `내보내기`가 “폴더를 선택할 수 없습니다. 데스크톱 Chrome이나 Edge에서 다시 시도해 주세요.”로 실패했다. ZCUT이 요구하는 `window.showDirectoryPicker`를 WKWebView가 제공하지 않았기 때문이다. 아래 로컬 수정본에서 앱 내부 내보내기를 적용하고 실제 MP4 저장·재생을 사용자 확인으로 검증했다.
2. **ZCUT AI 계정 연결:** 일반 ZCRE 웹 로그인과 ZCUT의 연결 동의는 별도 절차였다. 2026-11-25 사용자가 ZCUT 연결 권한을 승인한 뒤 연결을 완료했다. 같은 앱 저장소의 편집기에서 크레딧 577과 이미지·영상·오디오 모델 설정이 표시되고 `ZCRE 연결하기`가 사라지는 것을 확인했다.
3. **설치본의 앱 도구 메뉴 누락:** ZCRE 웹 왼쪽 메뉴의 `세로 영상 변환`은 설치된 앱의 지크 메뉴와 작업 창 도구 전환 목록에는 없었다. 해당 주소가 `ZCREQuickTool`에 없어 도구 선택 표시 및 창 제목도 이전 도구 이름으로 남는 경우가 있었다. 현재 소스에는 항목과 주소 매칭을 추가하고 관련 테스트 11개를 통과시켰다. 설치본에는 아직 반영하지 않았다.
4. **유료 결과 경로:** 새 생성·변환·번역 작업의 서버 처리, 크레딧 차감, 새 결과의 클라우드 저장과 후속 재사용은 이번 비과금 검증으로 확인할 수 없다. 기존 완료 결과의 미리보기와 일반 다운로드는 확인했다.

## 조치 순서

1. **앱 내부 내보내기 구현:** 공개된 편집기 코드는 `showDirectoryPicker({ mode: "readwrite", id: "zcut-export" })`로 폴더를 고르고 `queryPermission`이 `granted`인지 확인한 뒤 렌더링한다. ZCUT 주소에서만 이 폴더 선택 API를 제공한다. 실제 파일 쓰기는 해당 출처의 OPFS 폴더에서 처리하고, 완성된 MP4를 `blob:` 다운로드로 넘겨 기존 `WKDownloadDelegate` 저장 창에서 받는다. 2026-11-25 로컬 수정본 설치 후 사용자는 실제 프로젝트에서 **‘내보내기’ 버튼, MP4 저장·재생 성공**을 확인했다. 이후 확인된 결함은 다운로드 후 OPFS 폴더를 삭제해 **‘결과 폴더 다시 연결’이 이전 결과를 찾지 못하는 것**이었다. 현재 코드는 같은 폴더를 유지하고 재선택할 때 기존 MP4를 중복 다운로드하지 않도록 수정했다. Finder 저장 파일과 별도로 앱의 웹 저장소에도 결과가 남으므로 대형 영상의 저장 공간과 다른 macOS 버전의 호환성은 실기기 검증이 필요하다.
2. ZCUT 연결 승인 뒤 이미지 `seedream-5.5`, 영상 `seedance-2.5`, 오디오 `elevenlabs-v4`의 입력 메뉴가 열리고 참고 자료 추가 버튼이 표시됨을 확인했다. 효과음 모드는 `mirelo-sfx-2.0`을 표시했으며 원본 영상 첨부를 요구했다. 생성 버튼은 누르지 않았다. 앱 내부 내보내기를 지원하지 않는 이전 공개 버전에서는 `브라우저로 열기`가 임시 대안이다.
3. 세로 영상 변환 메뉴 수정본을 새 앱 빌드에 포함하고, 설치 후 웹 내부 이동 시 제목·선택 상태가 맞는지 화면에서 확인한다.
4. 최종 출시 검증에는 소액 생성 1건의 시작→진행→완료→미리보기→다운로드→재진입을 별도로 포함한다. 이번 결과만으로 신규 생성의 전체 성공을 선언하지 않는다.

참고: 화면에서 첨부를 제거한 파일이 ZCRE 서버의 임시 업로드 저장소에서도 즉시 삭제되는지는 확인하지 않았다. 이전 검증의 `reference-qa.png`는 ZCUT 보관함에 남아 있다.

## 연결 후 추가 검증 · 2026-11-25

- ZCUT 프로젝트 목록에서 기존 5초 프로젝트를 확인하고 편집기 주소로 재진입했다. 편집기에서는 클라우드 저장 표시, 타임라인의 텍스트 클립, 텍스트 속성, 자막 메뉴, 보관함의 기존 참조 파일을 확인했다.
- `내보내기 → 보관된 결과 → 다운로드`로 기존 클라우드 MP4를 다시 받았다. 67,296바이트의 5초 H.264 1920×1080 파일로 확인했다. 이 내려받기는 크레딧을 차감하지 않는다.
- 화면 밖 WebKit 검증 환경에서는 중앙 미리보기가 계속 `미리보기를 준비하고 있습니다`로 표시됐다. 이때 `document.visibilityState`가 `hidden`이고 오류 이벤트는 없었다. 백그라운드 렌더링이 멈추는 검증 환경의 한계일 수 있어, 이를 실제 앱의 재생 실패로 단정하지 않는다. 설치 앱의 화면이 보일 때 편집기 미리보기와 타임라인 재생은 별도로 확인해야 한다.
- 이미지·영상·오디오의 새 AI 생성, 참조 자료 업로드 후 결과 반영, 결과를 타임라인에 배치하는 전체 흐름은 이번 비과금 검증에 포함되지 않았다. 이 경로가 확인되기 전에는 ZCUT의 모든 기능이 검증됐다고 표시하거나 홍보 영상을 완성본으로 배포하지 않는다.

## 1크레딧 생성 시도 분석 · 2026-11-25

- 사용자 승인 후 `elevenlabs-v4`의 짧은 대본에 **1크레딧** 견적이 표시되고, 견적 API는 `can_submit=true`를 반환했다. 생성 버튼의 클릭 이벤트도 실행됐으나 생성 요청은 전송되지 않았다.
- 공개 ZCUT 편집기 스크립트의 제출 경로는 `held.pageIsHidden()`일 때 전송을 중단한다. 화면 밖 또는 뒤에 놓은 검증 창은 `document.visibilityState=hidden`이었다. 이 조건이 이번 백그라운드 생성 시도를 막은 것으로 판단한다. 임의로 이 보호 조건을 제거하거나 ZCUT의 제출 API를 직접 호출하지 않았다.
- ZCRE 잔액과 생성 기록을 다시 조회해 **577크레딧 유지, 신규 오디오 작업 없음**을 확인했다. 실제 앱 화면이 표시된 상태에서 승인된 한 건을 생성하고 시작→완료→편집기 배치→미리보기·저장을 재검증해야 한다.

## 실제 설치 앱 검증 · 2026-11-25

- 기존 프로세스를 종료한 뒤 수정본을 빌드·서명해 `/Applications/ZCRE 서포터.app`에 설치하고 새 프로세스 하나로 실행했다. 설치본과 `dist` 실행 파일 SHA-256은 일치한다.
- 앱의 도구 전환에서 ZCUT 프로젝트 목록으로 진입했고, 기존 5초 프로젝트를 열어 클라우드 저장 상태와 캔버스의 텍스트를 확인했다. 미리보기 재생 헤드는 00:05까지 이동하고 정지했다.
- 사용자 승인 범위인 `안녕하세요 지크입니다` 음성 1건을 `elevenlabs-v4`로 생성했다. 버튼에 1크레딧 견적이 표시됐고, 실제 잔액은 577→576으로 변했다. 작업 내역에 완료·타임라인 배치가 표시됐으며 재진입 후에도 오디오 클립과 결과가 남았다. 추가 생성은 하지 않았다.
- 오디오를 포함한 720p MP4를 내보내 macOS 저장 창으로 `/private/tmp/ZCUT-QA-20261125.mp4`에 받았다. 7.12초 H.264 1280×720 영상과 AAC 오디오가 있고, 오디오가 무음이 아님을 확인했다. 내보내기 뒤와 프로젝트 재진입 뒤 `결과 폴더 다시 연결`을 눌렀을 때 기존 MP4의 로컬 폴더 표시가 복구됐다.
- 이 검증은 위 프로젝트와 오디오 생성 경로의 성공을 증명한다. 이미지·영상 AI 생성, 대형 영상 내보내기, 다른 macOS 버전의 OPFS 호환성은 별도로 검증해야 한다.
