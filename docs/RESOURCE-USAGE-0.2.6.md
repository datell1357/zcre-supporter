# 0.2.6 최적화 관찰

2026-10-25 KST. 실제 계정의 데이터 조회는 계속 켠 상태이며 새 유료 작업은 생성하지 않았다.

## 변경 및 요청량

- 작업은 5초 목표 주기, 크레딧은 60초 및 작업 상태 전환/후속 정산 시 조회한다. 성공한 작업 조회가 잔액 조회 실패 때문에 사라지지 않는다.
- 초기 연결은 기존 최대 1,000개 탐색을 유지하고 이후에는 20개 단위로 필요한 페이지만 읽는다. 메모리에 최근 완료 기록 50개와 모든 미완료 작업을 유지한다.
- 정상·무변경 상태의 기본 요청량은 시간당 작업 약 720회 + 잔액 약 60회다. 초기 연결, 상태 전환 뒤 15초간의 후속 조회, 오래된 미완료 작업, 추가 페이지, 수동 새로고침, 웹 자체 요청/인증/서비스 상태 요청은 별도다. 5초마다 두 정보를 모두 읽는 약 1,440회와 비교한 계산이며 실제 네트워크 바이트 측정값은 아니다.
- 가상 시각 회귀 검사에서 2분의 25회 작업 확인 동안 크레딧은 2회 갱신됐다.

## 앱 본체 관찰

기존 0.2.5와 수정 0.2.6을 각각 약 30초씩 관찰했다. 상세 창을 닫고 지크 표시/산책 설정은 유지했다. 시스템 프로세스에서 이 프로젝트의 실행 파일 경로가 정확히 일치하는 프로세스 1개만 선택했고, CPU 누적 시간·physical footprint·인터럽트 깨우기 횟수만 읽었다. 인증 정보·패킷 내용은 수집하지 않았다.

| 항목 | 0.2.5 | 0.2.6 |
|---|---:|---:|
| 앱 본체 평균 CPU | 20.8% | 11.2% |
| 평균 physical footprint | 386.9 MiB | 369.2 MiB |
| 초당 인터럽트 깨우기 | 265.8 | 192.4 |

CPU 100%는 한 코어 기준이다. 무작위 산책 동작과 실행 경과 시간은 일치하지 않으며 통제된 벤치마크가 아니다. 메모리 차이를 이 변경의 효과로 단정하지 않는다. 이 측정은 WebKit/GPU/WindowServer 전체와 실제 배터리 방전량을 포함하지 않으므로 배터리 절감률 또는 장시간 소모량으로 환산할 수 없다. 변경 후 실제 전송량은 이번에 측정하지 않았다.

## 실제 계정 화면

재실행 후 기존 연결/28 Credit/완료 기록을 확인했다. 상세 화면에는 작업 확인 4초 전과 크레딧 확인 39초 전이 함께 표시돼 갱신 시각 분리를 확인했다. 지크 클릭으로 간소 카드가 열렸고 현재 완료 상태의 이미지 0/10·영상 0/6·합산 0/16이 표시됐다. 카드 닫기 후 일반 사용 상태로 두었다.

Swift 54개와 웹 브리지 32개가 통과했다. 실제 신규 생성→차감→완료→시스템 알림 전달의 전체 경로는 새 유료 생성을 수행하지 않아 이번 관찰로 확인하지 않았다.
